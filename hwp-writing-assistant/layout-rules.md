# hwpx 레이아웃 규칙 — 내어쓰기·어절 줄바꿈·캐시

실제 심사를 통과한 계획서의 hwpx XML 분석과, 사용자 HWP 왕복 저장 diff 실증에서 추출한
규칙이다. `scripts/hwpx_polish.py`가 ①②③④를 자동 수행하며, ⑤는 육안 마무리다.

## 1. 글자 겹침 금지 — 레이아웃 캐시 제거 (가장 중요)

hwpx의 각 문단에는 줄배치 캐시(`<hp:linesegarray>`)가 저장되어 있다. 문단을 복제하거나
텍스트를 프로그램으로 교체하면 이 캐시가 실제 텍스트와 어긋나 **글자가 겹쳐 보이는 치명적
렌더링 오류**가 발생한다.

- 텍스트를 변경한 문단(안전하게는 섹션 전체)의 `linesegarray`를 반드시 제거하여
  HWP가 파일을 열 때 줄배치를 재계산하도록 한다.
- `build_hwpx.py`로 생성한 파일도 예외가 아니다. **후처리를 건너뛰면 안 된다.**

## 2. 내어쓰기 정렬 — 줄바꿈 시 기호 아래로 떨어지지 않게

긴 문장이 다음 줄로 넘어갈 때, 이어지는 줄은 **기호(□ ○ - · ※)가 아니라 본문 텍스트
시작 위치에 정렬**되어야 한다(HWP의 Shift+Tab 내어쓰기).

원리: 내어쓰기 시 이어지는 줄 위치 = `left + |intent|`. 이 값이 문단 접두부(선행공백 + 기호 +
한 칸)의 실제 폭 `W`와 일치해야 '기호 뒤 첫 글자 시작점 정렬'이 된다.

- **자동 검증·교정(기본)**: 모든 글머리 문단에 대해 `W`를 계산(전각 1.0 / 반각 0.5 × 첫 run
  글자크기)하고, 기존 `(left+|intent|)`가 `W`와 오차(글자크기 × `tol_ratio`, 기본 0.25) 이내면
  보존하고, 벗어나면 `left=0` / `intent=-W` 인 교정 paraPr을 새로 만들어 연결한다. 선행 공백은 유지한다.
- **주의**: 서식 원본에 이미 내어쓰기 스타일이 있어도 그 값이 해당 문단의 접두부와 맞지 않을 수
  있으므로(예: 1수준 값이 2수준 문단에 걸려 있는 경우) **"음수 intent = 무조건 보존"으로 처리하면
  안 된다.** 반드시 폭 검증을 거친다.
- 사용자가 손으로 정밀 조정한 파일에는 의도적 커스텀 정렬(라벨 기준 정렬 등)이 있을 수 있으므로
  `tol_ratio`를 0.5로 넓혀 돌리거나, 교정 개수를 보고한 뒤 진행한다.
- 문단 앞 공백으로 계층을 흉내내는 방식은 금지 — 반드시 paraPr 내어쓰기로 구현한다.

## 3. 어절 단위 줄바꿈 — 단어가 줄 중간에서 끊기지 않게

한국어 공문서에서 "너구리가 줄을 타"처럼 단어가 줄 경계에서 잘리면 안 된다. 모든 줄의 첫 글자는
어절(띄어쓰기) 시작이어야 한다. 대응은 3단계이며 ①②는 자동이다.

1. **(자동) 줄나눔 기준 어절 설정**: 모든 paraPr의 `breakNonLatinWord="BREAK_WORD"`.

   > ⚠ **반전 매핑 경고 (실증 확인)**
   > OWPML의 이 속성은 **이름과 의미가 반대**다.
   > `BREAK_WORD` = **어절**(단어 경계에서 줄바꿈), `KEEP_WORD` = **글자**.
   > 사용자 HWP에서 어절 설정 후 저장한 파일을 diff하여 확정(2026-07).
   > 직관대로 `KEEP_WORD`를 쓰면 어절 문단을 글자 단위로 바꿔버리는 대참사가 난다.
   > `breakLatinWord`는 `KEEP_WORD`가 '단어'로 정상 매핑이므로 **그대로 둔다.**

2. **(자동, 휴리스틱) 장평 맞춤 — 안전 회랑(corridor) 방식**: 사용자 습관("윗줄 장평을 눌러 단어를
   끌어올림")의 자동화. 페이지/표 셀의 가용폭과 글자폭(전각=글자크기, 반각=1/2, ×장평 ±자간)으로
   문단의 줄배치를 시뮬레이션한다. 모든 줄에 대해
   `[줄 내용 폭 ≤ cap×(1-δ)]` **AND** `[다음 단어 첫 글자 포함 폭 ≥ cap×(1+δ)]`
   를 만족하는 장평 `r`(90~104%)을 줄마다 선택해 적용한다. 폭 모델 오차(±δ)가 있어도 실제 렌더링에서
   줄바꿈이 어절 경계에 오도록 보장한다.
   - 표 안 문단은 셀 폭(`cellSz`) 기준으로 계산한다.
   - 영문 비중이 큰 줄(45% 초과)은 건드리지 않는다 — HWP가 영문은 이미 단어 단위로 줄바꿈한다.

3. **(수동 마무리)** 시뮬레이션은 렌더링 근사이므로, ②에서 "조정 불가"로 리포트된 문단과 육안상
   어긋난 문단은 HWP에서 해당 줄만 블록 지정해 장평(90~98%)·자간(-3~-9)을 조정한다.
   긴 항목은 부연(`-`)으로 분리해 위험 자체를 줄이는 것도 방법이다.

**문서를 전달할 때는 ②의 조정/불가 문단 수를 반드시 함께 보고한다.**

## 4. 계층 좌여백

계층은 선행 공백이 아니라 `paraPr` 의 `left` 로 넣는다. 수준별 시작점은 `SKILL.md` 표를 따르며,
한 수준 = 본문 글자크기의 반 칸이다. 본문 크기는 **글머리 문단 중 최빈 크기**로 잡는다
(`※` 는 12pt라 이걸 기준으로 삼으면 계단이 어긋난다).

`paraPr` 은 `<hp:switch>` 안에 case/default **두 벌**이 들어 있다. 한 벌만 고치면 한글이
나머지를 읽어 값을 되돌리므로 반드시 전부 바꾼다.

## 5. 한글 실측 내어쓰기 (`hwpx_shifttab.py`)

2항의 계산값은 근사다. 양쪽정렬이 첫 줄 공백을 늘린 만큼 커서 x좌표가 달라져, 같은 `○ `
접두부라도 문단마다 값이 다르다(실측 −3018 / −3413 / −3307). 그래서 한글 COM 액션
`ParagraphShapeIndentAtCaret` 으로 한글에게 직접 시킨다.

한글은 저장하면서 **문단 여백을 바꿔놓는다** — 특히 내어쓰기가 없는 문단(요약 본문 등)을
엉뚱한 문단모양에 붙인다. 그래서 열기 전 값을 기억해 두었다가 저장 후 되돌린다.
글머리 문단은 **좌여백만** 되돌리고 내어쓰기는 한글이 잰 값을 유지한다.

## 6. 실행

```bash
python scripts/hwpx_polish.py <입력.hwpx> <출력.hwpx> [--no-indent] [--label-indent]
python scripts/hwpx_shifttab.py <문서.hwpx>            # 한글 없으면 종료코드 2로 건너뜀
```

- `--no-indent`: 내어쓰기 자동 적용을 끈다. 손으로 정밀 정렬한 파일에 쓴다.
- `--label-indent`: `○ (대상) …` 의 라벨까지 포함해 내어쓰기를 잡는다(기본 꺼짐).
- 처리 후 XML 정합성을 검증하고, `mimetype`을 무압축·최상단으로 두어 재패키징한다.
